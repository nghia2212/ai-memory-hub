## Separation of concerns
Hermes is orchestration logic, not the model. Define provider-neutral BrainAdapter interface: discover capabilities, invoke bounded structured planning/review request, return validated result with actual model/effort/auth mode/session ID, normalized usage/provenance/finish status and typed errors. Host runner executes supported subscription CLI adapters using structured args, no shell injection, no arbitrary command endpoint, no bypass permissions. Remote API adapters are opt-in and separate from subscription billing. Never pass access tokens to other providers. Keep planner prompts minimal; no source mounts for Hermes. Treat provider output and model registry content as untrusted data. Use strict JSON schema validation, reject invalid DAG, scope or unsupported actions. Deterministic policy engine exclusively authorizes actions, approvals, leases, spending and dispatch; model output is advisory.
## Routing hierarchy and controls
Tier 0 local rules and SQLite retrieval/forecast arithmetic; no LLM. Tier 1 eligible lightweight model for genuinely ambiguous small classification/summary tasks; Tier 2 preferred primary for plan/DAG/review; Tier 3 advanced for high uncertainty, architecture or bounded failed validation; secondary for availability/quality fallback. Escalate only with measurable reason, remaining approved budget and scope; cap retries and escalation depth, avoid recursive routing and planner loops. Prefer cheapest adequate verified model based on observed accepted-task cost, not brand labels or newest releases. Keep brain roles and execution agent model routing separate; primary planner does not need to execute coding. Dashboard configurable exact model/effort per role, priority list, allowed auth modes, task/session token and time caps, daily planner budget, escalation/fallback policy, enable/disable. Default manual approval for execution; planning itself may incur usage and requires separate standing permission/budget or local-only rules. Material change after approval invalidates plan unless within explicitly approved fallback policy. No automatic paid API fallback, production deploy or merge main.
## Session and quota accounting
Each planning/review/escalation invocation gets a bounded session linked to plan revision and task if applicable; reuse only if measured economical. Store input/output/cache/reasoning if exposed, actual model and auth mode, duration, provenance, errors, retries, accepted plan quality, forecast vs actual, estimated vs measured vs unavailable. Count planner cost in total job forecast, separately from executor cost; do not double count or equate context occupancy with subscription quota. Unknown quota remains unknown; account quota shared by planner/executors must not be double reserved. No fake usage or pricing. Use forecast cohorts and acceptance outcomes to suggest role changes, not silently change preferred brain. Candidate models from daily registry refresh need verified adapter/account compatibility and evidence before automatic use.
