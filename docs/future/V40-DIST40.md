# V4.0 DIST40 — Distributed AI Workspace
Status: PLANNED. Prerequisite accepted OPS35. Common gates ROADMAP.md. Branch lead/dist40-integration; A coordinator, B UI, C device adapters, D security/QA.
## Objective and non-goals
One authoritative local Hub with multiple explicitly enrolled runners: Windows laptop, other PCs, optional mobile/remote inference endpoints and cloud providers. Do not assume Android can run full coding CLI or reliable background service. No automatic public internet exposure, multi-master SQLite, distributed filesystem or unrestricted remote shell. Remote inference is distinct from remote code execution.
## P0 Lead — feasibility and threat model
Inventory actual devices/OS/RAM/network, model endpoints, battery/thermal constraints and connectivity. Verify client versions, transport, remote inference and runner capabilities using official documentation and actual smoke; benchmark local vs remote inference on representative workloads. Decide supported topology before implementation. If mobile endpoint not viable, retain manual/optional inference-only integration and disclose.
## P1 A+D — device identity and enrollment
Explicit pairing approval, per-device scoped identity, short-lived credentials, revocation/rotation, authenticated encrypted transport (e.g. approved private VPN plus service authentication); no public bind by default. Central Bridge owns authoritative state. Device catalog capability/OS/model/tool/version/project permissions, heartbeat and capacity with freshness; unknown != healthy. Audit and replay protection. Device compromise threat model and outbound classification policy.
## P2 A+C — distributed task dispatch
Central queue, capability/risk/data locality/budget/availability routing deterministic, explicit runner allowlist, resource reservation, lease fencing and idempotency keys. Runner outbound connection/polling, no arbitrary inbound commands. Signed or authenticated job envelope with approved revision, task/attempt, pinned skill/MCP, source reference, limits and permitted operations. Reject stale/replayed/unauthorized jobs. Cancel/pause semantics and reconciliation; offline runner cannot accept new tasks or continue beyond lease policy.
## P3 C — source and artifact handling
Explicit Git checkout/worktree per device only where authorized; verify repo/commit/hash, isolated workspace, no shared mutable directory, no arbitrary sync of secrets. Protected artifact manifests/hash/size, scoped transfers, staging, quarantine and review before Git delivery. Uncommitted checkpoint via approved protected patch reference, reject mismatch; no blind force push. For inference-only devices send minimal approved context, no source mount/write access. Preserve central handoff and skill versions.
## P4 C — hybrid model routing
Adapter for authorized remote local inference endpoint (Qwen/Ollama or other actually verified runtime), capability/latency/context/thermal and quota limits; choose local/cloud based on task policy and measured quality, not just price. No silent paid fallback. Phone sleep/thermal/network disconnect handled as unavailable/unknown; optional limits and opt-in. Validate model provenance where reported and unknown metrics.
## P5 B — distributed workspace UI
Device inventory/approval/revoke, health and capacity, execution placement reason, task/attempt map across devices, queue/budget, offline/quarantine/reconciliation, artifact evidence, data destination preview. Preserve P6A scoped filtering and no cross-project leakage. No fake device activity.
## P6 D — failure/security and performance
Test two authorized devices, stale lease, network partition, reconnect/replay, duplicate result, cancellation, revocation, artifact tamper, cross-project ID, prohibited data transfer, unauthorized endpoint and quota fallback. Distinguish at-least-once delivery from exactly-once side effects; use fencing/idempotency or manual reconciliation. Central backup/restore per OPS35. Measure latency/throughput/quality/resource use; no automatic scaling claims.
## P7 Lead — staged pilot and release
Phase 1 local single host regression; Phase 2 actual second trusted device inference-only; Phase 3 approved remote coding runner with isolated worktree; Phase 4 mixed workload and interruption tests. Phone optional if supported; do not claim supported without actual test. Test-V40.ps1, enrollment/revocation and recovery runbook, rollback disables remote dispatch without data loss. Gate: actual second-device authorized workflow, no unauthorized access or duplicate effects, real traces, honest coverage and user acceptance. No main merge/deployment without approval.
