# V3.4 KQ34 — Knowledge Quality Management
Status: PLANNED. Prerequisite accepted EX33. Common gates ROADMAP.md. Branch lead/kq34-integration; A requirements/data, B UI, C change/test integration, D quality.
## P0 Lead
Inventory verified/candidate/superseded memory, code index, SK32 registry, P6A, EX33 policy and checkpoint. Baseline stale/conflicting records using synthetic fixtures; map Git and test evidence contracts. No rewriting historical facts.
## P1 A — Requirement Registry
Stable requirement ID, project/scope, title, source approved requirement, revision, status draft/approved/implemented/verified/retired, priority, acceptance criteria, owner and provenance. Immutable approved revisions, explicit supersession/waiver, audit. Link requirement to task/plan, memory, skill, code paths/symbols, commit/PR and test cases/evidence via real IDs; many-to-many, project isolation, historical versions preserved. Verified only with matching version and evidence, not task success alone.
## P2 C+A — impact analysis and regression
Compare baseline and proposed Git diff with scoped path/symbol/dependency links; distinguish certain from potential and unknown impacts; show changed/deleted symbols and stale indexes. Select required regression tests from approved links; no arbitrary commands from memory; use approved test catalog and isolated runner. Missing tests/evidence flagged; block release for mandatory uncovered requirements unless authorized non-security waiver. No inference that unlinked requirement is unaffected. Integrate plan and QA gates, preserve EX33 fast path only when risk permits.
## P3 D+A — memory freshness
Freshness separate from verification history: current/needs_review/stale/unknown with reason, checked_at, evidence commit/hash/symbol, policy and reviewer. Trigger on relevant diff/index refresh, ADR/spec revision, dependency/version change or type-specific review interval; TTL alone cannot invalidate durable business facts. Missing evidence -> unknown/review. Bounded incremental scan, dedupe, explicit conflict candidates. Default context pack excludes stale/needs_review unless approved explicit historical request; warn required context unavailable. Human reverify/supersede/archive, never silently delete or promote. Scope worktree differences correctly; no global invalidation based on one feature branch.
## P4 D+C — Skill quality
Static manifest/dependency compatibility, missing MCP/tool, client version drift, conflicting scope rules, budget and reference hashes. Candidate patch from verified outcomes; reviewer approves immutable new version; preserve running snapshot. Usage/effectiveness with matched QA evidence; selection/delivery != compliance. Detect known conflicts deterministically; semantic conflicts may need human review, optional authorized LLM. No arbitrary script execution.
## P5 B — Dashboard
Requirement list/revision/traceability matrix, affected requirements from diff, missing coverage, regression status, memory review queue with reason/evidence, skill quality/dependency alerts, approve/reject/supersede/archive and audit. Filter by project/plan/task; bulk actions preview, auth/CSRF, safe rendering. Link P6A.
## P6 D — knowledge maintenance
Review queue ranking by risk/change recency, dedupe without loss, configurable retention/export, archive restore; separate conversations from authoritative requirements. Project-specific content stays local; synthetic public fixtures only. Measure review burden, retrieval relevance and regression detection; no unsupported accuracy claims.
## P7 Lead — E2E and release
Synthetic two-project case: approved requirement tied to test and symbol, edit/delete symbol triggers impact and freshness, failing/missing test blocks mandatory acceptance, corrected test verifies new revision, old history intact. Conflict, stale index, branch divergence, scope leakage, malicious import, rollback tests. Actual permitted repository smoke with user-approved data, Test-V34.ps1 and common gates. Require accurate evidence/unknown states and no loss of earlier functionality.
