# V3.3 EX33 — Adaptive Execution & Model Continuity
Status: PLANNED. Prerequisite: accepted SK32 including P6A. Apply common gates in ROADMAP.md. Planned branch lead/ex33-integration; agents agent/ex33-policy, agent/ex33-ui, agent/ex33-runner, agent/ex33-qa.
## Objective
Reduce friction and orchestration overhead while preserving policy, deterministic routing and continuity when quota/network/client fails.
## P0 Lead — inventory
Audit existing plan/revision, lease, quota, model catalog, runner, handoff, context pack, SK32 snapshots and P6A filters. Reuse actual contracts; map current read/write capabilities and provider-specific quota signals. Baseline comparable small/medium/large tasks and collect coverage.
## P1 A — execution policy
Fast: deterministic read-only by default; scoped low-risk edits only with explicit prior policy, file allowlist, isolated worktree, bounded diff/time/budget and required QA. Standard: plan + review/approval + one primary agent + QA. Advanced: DAG, multiple agents, isolated worktrees, integration review. Router rule-based on capabilities, write scope, risk and dependencies, explain choice, allow user override only within policy. Ambiguity escalates; no auto-approval of merge/deploy, credentials, external writes, destructive changes or restricted data. Record policy version and approval evidence even in fast mode.
## P2 A+D — outbound data controls (minimum security foundation)
Classify Public/Internal/Confidential/Restricted per project and source; default unknown deny outbound for protected projects. Intersect provider allowlist, project/worktree, identity, tool and purpose; redact/minimize before sending memory/code/skills/attachments/telemetry. No raw content in audit. Local model not automatically authorized for restricted data; require organizational policy. Block unsupported enforcement paths, distinguish external IDE coverage from Hub-managed calls. Test denial and no secret leakage.
## P3 C — checkpoint and continuity
Immutable checkpoint per task/attempt: approved revision/hash, Git HEAD/branch/worktree and dirty file hashes or protected local patch reference, completed steps, pending actions, test evidence, context and pinned skill/MCP versions, permissions, budget ledger and unresolved side effects. Do not commit dirty secrets or transfer private reasoning. Atomic checkpoint and idempotent transitions; lease fencing, old runner stop/ack or quarantine before next claim. Unknown outcome requires reconciliation, never blind retry.
## P4 C+A — quota and fallback
Normalize provider-reported quota exhausted/rate limited/auth/network/unknown without guessing reset; distinguish subscription vs API. Candidate routing based on capability, authorized data destination, effective model evidence, context limit, tool/skill compatibility, remaining budget. No silent model substitution or paid fallback. Explicit preapproved fallback policy or user approval; otherwise pause. New attempt same logical task, preserve revision/snapshot, record actual model and coverage. Validate Git state and dependency versions before resume; changed state triggers replan. Use adapters only after actual CLI contract verification.
## P5 B — dashboard
Mode selector + reason, policy editor, quota/blocked state, checkpoint preview, proposed replacement model and cost coverage, approve/pause/resume, history and P6A task/attempt view. Show unknown/unsupported and reconciliation actions. No auto-refresh scope leak.
## P6 D — orchestration analytics
Track role/category: classification/planning/routing/execution/QA/summary; distinguish rule-only from model calls. Ratio = measured orchestration tokens / measured total tokens for same scope and accounting convention; null if incomplete, disclose coverage. Compare identical tasks with quality gate; include end-to-end latency and operator clicks. Avoid cache/reasoning double count.
## P7 Lead+C — real E2E
Simulate quota/error safely with fixture, plus actual permitted cross-client handoff Claude/Codex or available Gemini, without intentionally burning quota. Verify dirty-worktree checkpoint, stop old runner, same skill version, resume with new attempt, tests and trace. Qwen/local only if installed and capable; unsupported not PASS. Crash, duplicate dispatch, uncertain side effect, quota exhausted and denied provider negative tests.
## P8 Lead — release
Test-V33.ps1, backup/migration/rollback, regression SK32/P6A/V3.1, Windows browser and actual handoff evidence. Report per common gate. Gate: fast read-only has no manual approval when policy permits, unsafe action blocked, scoped edit cannot escape, fallback preserves checkpoint and no duplicate effects, analytics honest. If real cross-client smoke unavailable, remain blocked for full acceptance.
