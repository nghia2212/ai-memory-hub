# V3.5 OPS35 — Self-Managing Platform
Status: PLANNED. Prerequisite accepted KQ34. Common gates ROADMAP.md. Branch lead/ops35-integration; A health/jobs, B UI, C adapters/resources, D recovery/security.
## P0 Lead
Inventory actual Docker/WSL2/host services, health routes, indexes, leases, disk, DB, adapter versions, backup and policy coverage. Baseline idle/active/reindex RAM CPU disk and latency on user's machine when available; distinguish cap vs measured. No invasive host probing without permission.
## P1 A — health and diagnostics
Unified checks for Dashboard/Bridge/Codebase/Hermes optional/host runner, auth, DB readiness/integrity via safe bounded checks, index freshness, mount mapping, job/lease orphan, disk space, backup age, token collector lag. Healthy/degraded/unavailable/unknown/disabled, timestamp, source, actionable reason. Timeouts, backoff, jitter, dedupe, no expensive query on every poll. Local notifications configurable. No credential or raw transcript logging.
## P2 C — adapter compatibility
Version/capability inventory and fixture contracts for CLI hooks, usage and conversation formats, native skill/context delivery, MCP transport; detect format/version drift, quarantine malformed records, incremental cursors, dedupe, report coverage gap. Never auto-download/upgrade CLI or change user config; preview and backup then explicit approval. No model invocation for probes unless approved.
## P3 C+A — resource profiles
Lite: Bridge/Codebase/Dashboard, optional collectors paused. Standard: core+host runner+bounded collectors, Hermes off unless enabled. Full: optional Hermes and configured local inference; budget CPU/RAM/concurrency, queue heavy reindex and pause nonessential work, adaptive polling and backpressure. Profile changes preserve DB, task snapshots and active leases; do not stop active work silently. Windows/WSL2 settings changes explicit approval. Benchmark on 16GB target where available; no invented fixed savings. Index scoped incremental refresh where supported; measure before changing storage/mount strategy.
## P4 D — backup and recovery
Consistent online SQLite backup, manifest/schema/hash, scoped config and index rebuild plan, encrypted/protected storage as appropriate; exclude secrets from exports and Git. Retention, disk quota and restore verification to isolated instance, define measured recovery time/data loss and report against owner-approved objectives. Test corrupted/missing backup, migration failure, restart and lease fencing; no live overwrite without approval. Provide rollback runbook; preserve backup before upgrade.
## P5 A+B — repair workflows
Diagnose -> proposed action/diff -> approval -> bounded action -> verify -> audit. Read-only diagnostics may run automatically. Only explicitly approved low-risk idempotent actions can auto-run; never restart active runners, reset DB, delete volumes, modify firewall or install arbitrary packages autonomously. Unknown outcomes pause and reconcile. System Health UI with status, trend, action, history, profile, backup/restore drill, compatibility and dependency map.
## P6 D — operational security
Validate data classification and outbound enforcement EX33 across new collectors/repair tools, rotation of local credentials with no exposure, dependency inventory and pinned versions, security update review. No Docker socket or uncontrolled host command endpoint. Test unauthorized action, secret redaction, restricted export and malicious diagnostic payload.
## P7 Lead — acceptance
Inject service outage, stale index, malformed log, expired lease, disk threshold in isolated tests; verify truthful health and recovery suggestions, restore drill, profile switching with active work, no lost task, measured resources and prior regression. Test-V35.ps1 read-only default and actual Windows smoke. User approves operational runbook and backup restore evidence before DIST40.
