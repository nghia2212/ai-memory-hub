## Product thesis
Local-first AI Agent Control Center for individual developers who already use multiple AI tools, later small teams. Bring your own API credentials or supported IDE/CLI subscriptions; no resale or unauthorized reuse of provider subscriptions, no credential extraction. Self-hosted initially, optional paid Pro software. Differentiators to validate: cross-client project continuity; scoped Memory/Skill/MCP; observable task-level execution; quality-adjusted cost and effort reduction. English-first launch with Vietnamese option. No claim of savings, full IDE control, or enterprise readiness before evidence.

## COM0 — Technical alpha / V3.2.1 (indicative months 1–2)
- Founder + Lead: complete P0–P20 with honest live gates, including one approved real managed API task, provider usage, real MCP handshake and external Plan linkage. Do not require unavailable IDE token counters for unsupported clients; document coverage. Existing release approvals apply.
- Product inventory: target persona, 3 repeatable workflows (small Java bug fix on public synthetic project, TypeScript/Three.js feature on public/synthetic project, cross-client handoff), sample data with no child/customer/bank/internal source.
- License/IP gate before public packaging: review repo history, contributor ownership and employer obligations, AI-generated code/assets, dependency/SBOM and third-party license notices, MCP redistributability and provider terms; check product name/trademark. Founder chooses closed source vs open core; current public repo cannot retract old copies. No automatic license or visibility changes. Keep proprietary planning/secrets private; this public document contains generic planning only. Seek qualified legal/tax advice where needed.
- Clean Windows install on a separate test environment, documented prerequisites, uninstall preserving data, backup/restore, safe update, English quickstart, health diagnostics, redacted support bundle; measure RAM on 16GB target. No auto-install or live restart without approval.
- Benchmark protocol: paired same task/repo baseline/model/settings/permissions, randomized or alternating order, repeated runs, QA acceptance, input/cache/output/reasoning where supported, estimated API cost, elapsed time and operator effort; separate measured vs estimated vs unknown and subscription usage. Include failures/retries, no selection bias, no private data, no extra paid calls without budget.
- Gate: no critical security/data-loss issues; successful clean install and restore; at least one approved real API workflow with measured usage; 10 paired pilot tasks planned and baseline evidence available. Technical alpha only, no sales claims.

## COM1 — Private beta / V3.3 EX33 (indicative months 3–4)
- Preserve EX33 Fast/Standard/Advanced, outbound controls, checkpoint continuity, quota/fallback and orchestration analytics. Add bounded context/cache optimization only as approved technical addendum, not replacement of EX33.
- Interview 10–15 target developers; recruit 10–30 opt-in testers through permitted community channels, GitHub demo/landing page, no spam. Start private; public beta only after safety and usability review. English video/demo and docs, onboarding wizard, opt-in feedback, issue template and known limitations.
- Test first-value workflow: connect one project and provider/client, run a scoped task, see Memory reuse and trace; target at least 70% of testers who attempt onboarding reach first value within 30 minutes, at least 40% of activated testers use again in week 2, collect denominators and reasons for dropout. Targets not observed metrics.
- Aim for at least 20 paired benchmark tasks covering small/medium/large and failed cases; target median API cost reduction >=20% among comparable successful tasks without material QA regression; report all-task success, cost per accepted task, latency and coverage. If no savings, test continuity/time-saving positioning instead. Do not claim unsupported IDE savings.
- Pricing discovery interviews and opt-in willingness-to-pay; target 5 users willing to pay or at least 3 paid-pilot commitments after demonstration. No charge before terms, refunds and payment readiness.
- Gate: no unresolved critical security/data-loss issues, documented provider compatibility, usable onboarding, credible repeated value evidence and willingness-to-pay. If unmet, iterate or narrow persona rather than rush paid launch.

## COM4 — Enterprise feasibility / V4.0 DIST40 (indicative months 10–12)
- Preserve DIST40 enrolled remote runners, device identity, authenticated transport, lease fencing, protected artifacts, remote inference vs remote execution distinction and second-device smoke. No public internet exposure by default.
- Enterprise additions separate: on-prem deployment, SSO/role integration, audit export, data residency and egress policy, signed updates/SBOM/vulnerability disclosure, incident response, retention and backup, deployment guide, support/SLA only as contractually achievable. Independent penetration test and risk review before regulated production. No bank/customer data in demo, benchmark or unapproved external API. No certification claims absent actual certification.
- Start one non-sensitive design-partner pilot with explicit scope; propose pricing from USD 299/month only as discovery, plus onboarding/support by quote, not guaranteed market rate. Enterprise release gated on actual procurement/security acceptance and operational support. Defer regulated bank sales until requirements met.

## Metrics / decision cadence
Monthly founder review: activated users, week-2/week-4 retention (cohort denominators), paid conversion, churn, MRR (net of discounts/refunds, not profit), cost per accepted task, QA pass rate, coverage, support hours, installer success, critical defects, paid acquisition cost if applicable. Record baseline and sample size, avoid false precision. Targets: 10–30 beta users; 5 paid Pro pilot customers; 3 team pilot customers; 1 enterprise design partner. These are milestones, not sales forecast.
Cost model: BYOK separates inference from subscription; founder support time, packaging/signing, hosting/merchant fees, refunds/tax and security review still cost money. Scenario only: 50 Pro x $9.99 + 5 Team x $49 = $744.50 gross monthly before expenses. Start with near-zero paid marketing; cap any spend via explicit approval. Review kill/pivot criteria after beta: no repeat use or no willingness to pay despite fixes => narrow use case, revise pricing, or pause sales.

## Execution and governance
COM0–COM4 are a parallel commercial backlog, not automatic technical dispatch. Lead owns product gates; Agent A benchmark/metrics, B UX/docs/demo, C packaging/compatibility, D security/license inventory and QA; founder owns licensing, actual customer contact, pricing, spending, legal approval, publishing and release. Agents may prepare drafts and synthetic fixtures, not contact people, buy services, publish marketing, change repo visibility/license or process payments without explicit approval.
Maintain a separate private commercial STATUS/backlog for customer identities and results; public repo only generic/redacted docs. Each COM gate requires evidence, commit, tests, risks, decision and next actions. Use separate worktrees and draft PRs; no merge main or activation of next technical release without user acceptance. Start COM0 nonconflicting planning and audit; implementation waits for agreed runtime baseline. Do not build payment/licensing before beta evidence unless founder explicitly approves.
