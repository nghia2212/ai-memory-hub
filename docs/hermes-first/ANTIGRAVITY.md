# Hermes-first UI and Antigravity pilot

Default start uses Hermes dashboard at 9119; legacy dashboard at 8080 is an opt-in rollback (Compose profile legacy). No migration or deletion of old data. Drain existing tasks and stop both old UI and host runner before switching branches/config. Use the unified start launcher; it enables the project-owned plugin once in the persistent volume, mounts plugin source read-only, and checks real Docker-to-host status. If Hermes is already running, drain and stop it before upgrading plugin/config.

The AI Memory Hub tab displays Windows CLI detection and operator configuration only. Hermes native Chat/Kanban/Skills/MCP/session UI is the main interface. The plugin registers hub_antigravity_status and hub_antigravity_analyze. The latter is a bounded synchronous tool, NOT a durable external Kanban lane. Use Hermes's native task lifecycle, request review before marking a card done, never retry an uncertain result blindly.

Antigravity execution is disabled by default. Install/authenticate official agy on Windows using Google supported login. For a disposable registered worktree only, set in local ignored .env:
 
    HERMES_AGY_ENABLED=true
    HERMES_AGY_PROJECT_ID=<registered UUID>
    HERMES_AGY_WORKTREE_ID=<registered UUID>
    HERMES_AGY_MODEL=<exact live agy models selector>

Do not point to a production repo or store secrets in that worktree. Restart the Host Brain Agent after changing configuration. Dedicated token is generated by init-env; no general runner token passed to Hermes. Host verifies registered scope, fixed operator model, real CLI flags and model list, plan + sandbox flags, one concurrent invocation. Actual sandbox enforcement and compatibility must be tested on the installed agy; do not assume plan flag alone is a security boundary. No permission-bypass flags, no API fallback. Native .exe is required on Windows for this pilot, other launcher types are rejected. Model auth and quota remain unknown until actual evidence. Use status tool first; then explicitly request analysis of a synthetic task in Hermes Chat. CLI output may be text or JSON depending on live help. No fabricated usage.

Pending: host Docker reachability, runtime plugin enable/load, real CLI smoke test, durable task correlation/checkpoints, cancellation, recovery, external Kanban lane, policy-aware model selection, plan artifacts, business workspace/memory/telemetry plugins. Do not remove legacy UI until all gates pass.

References: Hermes v0.23.4 official plugin developer guide, dashboard extension guide, optional antigravity-cli skill and Kanban worker lanes.
