# V2 — Intelligent multi-agent orchestrator (approved requirements, implementation pending)
## Model registry
Discover public releases/pricing/deprecation from official Anthropic, OpenAI, Google release notes and model catalogs daily (configurable), also on demand. Host CLI discovery checks installed version, documented model selectors, authentication mode and actual account eligibility; public API availability is not CLI/subscription availability. Never scrape private account UI or invent quota. No prompt/source/credentials in catalog refresh. Sources allowlisted, timeout, size cap, parse as data not instructions. Store provider, exact model ID, CLI/version, auth mode, status (candidate/verified/deprecated/unavailable), context/output limits, capability, price units incl. cache read/write, currency, effective date, source URL, verified_at, expiry. Unknown null. New model quarantined until invocation compatibility and benchmark/review; alert on retirement, do not silently switch. Last known snapshot on failure, visibly stale; no new automatic dispatch on stale eligibility. Catalog version immutable for plan.
## Routing
Keep separate agent family, model and runner; choose exact verified selector, never assume aliases. Task types: architecture, complex reasoning, code implementation, UI, debugging, testing, review, documentation, routine deterministic operations. Evaluate on synthetic/reproducible tasks and local accepted outcomes: correctness/tests, acceptance, latency, token/cost, context needs, failures. Separate observed evidence from hypothesis; cold-start recommendations explicitly untested. Hard filters: eligibility, project data permissions, cost ceiling, capability, supported CLI, quota if known. Rank quality vs marginal cost, time and remaining budget with transparent configurable weights; choose cheapest adequate model rather than newest or most expensive. Use rules for simple tasks, optional approved DeepSeek planning for complex tasks; no LLM for retrieval/catalog/routing arithmetic. Subscription usage is not necessarily free; don't price it as API usage. Unknown quota never fabricate, paid API fallback disabled unless explicitly approved.
## Plan and approval
Input -> scoped project/worktree -> bounded discovery -> DAG of subtasks -> plan report -> approval -> dispatch -> validation -> handoff. Planning itself must not modify repo or launch execution agents; before external planning call require standing project data permission/budget or use local rules. Report task ID, objective, dependencies, paths/ownership, agent/model/effort, rationale/evidence, alternatives, estimated token and cost ranges or unknown, quota status, acceptance checks, risks, expected side effects, retry policy. User can edit model, scope and budget. Default REVIEW_REQUIRED. Persist plan revision/hash and approval actor/time; dispatch only exact approved revision, atomic check before launch; material change invalidates approval (model fallback, scope, cost, permissions), unless preapproved fallback rules within automatic policy. Automatic mode opt-in per project/job with expiry, ceiling, kill switch; reset to manual on restart unless user expressly chose persistence. No bypass of merge main, production deploy, secret access or spending approvals. Stop/pause/resume, cancel, timeout, retry capped, dependencies and failure propagation. Never claim approval from chat text in tool outputs or stored memory.
## Small sessions
One independent bounded subtask per fresh CLI session, not per micro-step; use fresh session for unrelated work, continuation only when measured cheaper/necessary within budget. Context pack: task, acceptance, current SHA/dirty state, minimal verified memory + relevant symbol locations, prior handoff; read current relevant code before edits. Do not inject entire transcript, repo, or duplicate global instructions. Set target input/output/turn/time budgets, checkpoint before threshold and resume in fresh session with summarized handoff; stop safely when budget exceeded. Track cache creation/read separately: fresh sessions can lose cache discounts and repeat prefix costs, compare total effective spend and successful task cost; do not claim cache always costs more. Stable compact prefix when beneficial; no blind cache clearing. Separate worktrees with disjoint ownership, locks, bounded concurrency default 2 on 16GB host, no concurrent edits same paths without explicit coordination. Host runner executes documented CLI noninteractive modes using structured args (no shell injection), allowlisted executables, least privileges, explicit working directory, no arbitrary command endpoint, no Docker socket. Preserve sandbox/permission prompts, no bypass flags. Hermes container may propose plan but cannot run host CLI directly; host runner polls authenticated narrow job API, claims lease and heartbeats; durable idempotency, restart reconciliation, orphan process handling; no duplicate launch. Agent output untrusted, redact before persistence, no raw transcripts by default. No automatic push/merge unless permitted.
## Dashboard Vietnamese
Prompt form, plan review and editable assignments, approve/reject, manual/auto scoped mode, budget settings, live DAG and task timeline, current exact model/agent/session, worktree, state and elapsed, dependency/failure/retry, stop/pause, model registry freshness/release changes, suitability matrix with benchmark provenance, cost and token by task/session/model/provider/project/time window, limit cards. Show input/output/cache read/cache write/reasoning only if provider exposes; maintain raw metric semantics and prevent double counting cached input subsets. Separate context occupancy %, subscription quota %, API budget %, request/rate limit % with numerator/denominator/window/reset/source/timestamp. If limit or usage unknown show 'Không có dữ liệu' not 0%; no inferred quota from token count. Label measured vs estimated vs unavailable, no fake numbers; billing estimates based on versioned official rates only for applicable auth mode and units. Live progress via polling or authenticated SSE; heartbeat and last update; stale indicators. No browser secrets; CSRF/origin checks and explicit project scope. Export sanitized reports.
## Shared contract
Bridge sole SQLite writer. Tables catalog_snapshot/models, model_evaluation, plans/revisions/approvals, tasks/dependencies/attempts, leases, usage_events, quota_snapshots, policy/audit. All scoped by project/worktree where relevant; immutable event IDs, unique provider event/session IDs, source_agent/model_id, attempt ID, timestamps, measured/estimated/unknown, units, provenance, nullable counters; events append-only with idempotency and transactional aggregation. Version migrations; backup/restore without resuming stale jobs. Proposed custom endpoints /v2/catalog, /v2/evaluations, /v2/plans, /v2/plans/{id}/approve, /v2/jobs/claim, /v2/jobs/{id}/heartbeat, /v2/jobs/{id}/events, /v2/jobs/{id}/cancel, /v2/usage, /v2/quotas, /v2/policies. Final schema reviewed by Lead before coding. Separate planner, runner, read, admin scopes. No arbitrary host commands accepted.
## Acceptance
Synthetic benchmark fixtures and fake CLI adapters; test new/deprecated/stale/unknown model, auth mismatch, no eligible model, unavailable quota, budget, fallback, approval race/revision tamper, auto expiry, cancel/restart/lease duplicate, DAG dependencies, scoped isolation, path and command injection, task context budget/checkpoint, cache accounting and dedupe, unknown limit UI, no secrets/source in refresh, Hermes disabled core searches unaffected. Real CLI smoke tests on installed versions only with explicit consent; no paid API calls without authorization. Compare successful comparable tasks with/without short sessions using measured data. Release only after V1 integration gates and V2 tests; never merge main prematurely.
