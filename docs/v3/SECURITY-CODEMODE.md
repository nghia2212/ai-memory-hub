# Security, supply chain and Code Mode
Threats: malicious manifest/package, poisoned tool descriptions/results, prompt injection, cross-project leak, confused deputy, path traversal/symlinks/junctions, SSRF/DNS rebinding, localhost privilege abuse, credential exposure, arbitrary host execution, runaway resource/cost, lost acknowledgement/duplicate side effects.
Default deny. Owner explicitly approves install, permission scope and revision; immutable manifest canonical hash and artifact SHA/image digest; verify release origin/license/signature when available, lock deps, no latest tag, no install-time secrets, no autonomous package upgrades. Import JSON inert, reject unknown fields, shell operators not interpreted, resolve exact approved executable; package scripts themselves are untrusted. Quarantine until security review and smoke. Windows native tools may not be strongly isolated; require constrained account or VM/container for untrusted code; do not advertise Job Objects as security boundary. No broad mounts, no admin, no host Docker socket, no access to user credential stores except narrow secret broker. Filesystem realpath and junction checks at use time, read-only default, allowed worktree writes only. Remote HTTP allowlist, TLS, DNS/IP checks and redirect validation, deny metadata/internal network by default except explicit approved loopback services, no token forwarding across origins. Separate project/company data classes; bank data default blocked from external AI/MCP, use synthetic DEV/UAT only unless organization authorizes.
## Code Mode
Use stable discovery/schema/invoke/execute facade. Verify FastMCP Code Mode and Monty exact version and security claims in disposable test. Candidate alternate Docker MCP Code Mode only after independent security/reliability tests. Minimal sandbox with no filesystem/network/process/env/import escape, only injected mediated async tool capability. If runtime cannot guarantee isolation, disable code execution and use direct calls. Bound wall time 30s, calls 20, output 4000 chars, script 16KiB, memory target 256 MiB, concurrency 1 defaults; reject or queue above limits; enforce in host runner, not merely prompt. No unbounded loops/recursion, stop/cancel, nested calls forbidden; separate approved workflow with higher caps if needed. Validate tool arguments against pinned schemas and policy every call, including downstream writes/network; tainted output never grants permissions. Treat upstream readOnlyHint/destructiveHint as untrusted hints; explicit verified per-tool classification; unknown deny. No shell/SQL/Python generic write tool by default. Blender Python runs outside gateway sandbox: restrict to dedicated approved scripts or owner-reviewed isolated copy; no claim of sandboxing bpy. SQLcl read-only account and DB policy, no production. Git push/merge/deploy separate explicit approval. Never auto-retry uncertain non-idempotent action; record uncertain and reconcile.
## Audit & privacy
Record actor/scope/lease/tool revision/schema hash/approval/decision/timestamps/duration/size/outcome; redact paths/tokens/PII, raw args/results/scripts opt-in encrypted local only, default metadata 180 days configurable. Credentials referenced, not exported. Workflow script source stored only after user approval; scan/redact and prevent embedded credentials. External egress includes cloud model context, not just MCP network. Test audit integrity, privacy deletion and restore. Kill switch deny future calls, drain/cancel safely, no unrelated process termination.
