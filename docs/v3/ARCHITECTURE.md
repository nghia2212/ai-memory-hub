# Architecture and lifecycle
## Components
1. Existing Memory Bridge persists registry, immutable revision, project grants, profiles, leases, events, usage and workflow records; DB migrations after V2 latest, sole writer.
2. New gateway exposes stable read-only discovery and approved invocation facade to Claude/Codex/Gemini/agy; supports Streamable HTTP loopback with auth, optional stdio shim. No direct agent-to-backend bypass; namespaced immutable IDs. Direct legacy core endpoints remain during migration with same RBAC.
3. MCP manager reconciles desired state to actual runtime via authenticated narrow host runner; no arbitrary command API. Host runner uses owner-reviewed immutable manifest and package digest, approved executable path and argv array, constrained cwd/env; Windows Job Objects where suitable, restricted account/process sandbox, no shell by default. Docker broker on host may launch only registered pinned image with reviewed mounts/limits/network; no socket mounted into gateway/agents. Host agent is explicitly installed and paired, not a remote execution service.
4. Code Mode runner separate sandbox process/container; only mediated tool call capability, bounded resource budget; optional pinned FastMCP Code Mode/Monty after verification, otherwise direct facade. Never assume upstream sandbox enforces downstream tool side effects.
5. Existing V2 planner proposes profiles/tools, costs, permissions and revisions. Policy engine evaluates deterministic grants before start and every invocation. Dashboard is server-side proxy; never directly exposes credentials or runtime handles.
## Runtime adapter kinds
- stdio executable: Python uv/venv, Node pinned package, Java CLI, preinstalled binary. Install in per-plugin isolated environment; no arbitrary install hook outside approved policy.
- container stdio/HTTP: pinned digest, readonly root if compatible, explicit mounts, nonroot, drop caps, resource limits, no privileged/network default.
- local HTTP / remote HTTPS: connect to existing service; do not claim process ownership. Legacy SSE optional compatibility after tests.
- desktop bridge: Blender/IntelliJ controlled via explicit supported addon/IDE session; never terminate user-owned process; document GUI/manual dependencies.
- tool wrapper: approved predefined Java/CLI workflow with typed parameters; registering a new wrapper implementation may require plugin package development, not core redeploy.
## Lifecycle
Registry states DRAFT, QUARANTINED, VERIFIED, RETIRED; installation states ABSENT, INSTALLING, INSTALLED, FAILED, UPDATING, ROLLING_BACK; runtime states STOPPED, STARTING, READY, BUSY, DRAINING, FAILED, EXTERNAL_UNAVAILABLE. Independent enabled flag and grants. Discover initialize/tools/list (pagination bounded), persist schema hash and capability candidate; tool descriptions/annotations untrusted. Notifications tools/list_changed trigger refresh; polling fallback, invalidate stale cache on revision. Pin plan to plugin/tool schema revision and permission snapshot, block changed tool until reapproval. Stable search facade returns scoped subset; no cross-project metadata leaks.
## Resource and concurrency
On demand by default; manual pin and always-on only owner-approved. Dependency DAG acyclic. Start acquires lease and atomic reservation under lock; shared instances only stateless/same security domain; stateful Serena/IDE/browser/DB session scoped by project/worktree and credential identity, Blender exclusive write lease per scene. Lease heartbeat TTL 60s (config), 15s heartbeat, reconcile expired lease and crash; never automatically replay writes with unknown outcome. Idle timeout default 600s, reference counting, drain after last lease, checkpoint before stopping managed process. Disable rejects new calls, drains; emergency revoke cancels where supported and marks uncertain outcomes, not kill unrelated apps. Remote connection close does not stop server.
Initial budgets: 16 GiB laptop; preserve >=3 GiB available physical RAM, dynamic measured host pressure; core target <=2 GiB working set, optional MCP pool target <=4 GiB, <=2 agent jobs and <=1 heavyweight Blender/browser/IDE job by default; tune after measurements. WSL overhead and child trees included when measurable, never sum overlapping metrics; distinguish enforced limit vs estimate vs measured. Queue with fairness, priority, timeout and cancellation; if insufficient capacity deny/defer, no unapproved eviction. Docker profiles only for infrastructure; runtime installation uses manifests, not regenerate compose. No restart of hub on registry changes; atomic cache reload with revision and health probe.
## Data layout
Owner-configurable default D:\\AI-Memory-Hub-Data; registry SQLite via Bridge, plugins/<id>/<revision>, envs, artifacts, workflow revisions, redacted logs, backups. No source repo dependency for runtime config. ACL per owner, DPAPI/Credential Manager secret references via host broker; container secrets provisioned narrowly, no plaintext in registry/export. Backup manifest/DB/workflows consistent; secrets excluded or separately encrypted owner export; restore quarantine until paths/digests/grants verified.
## Failure modes
Gateway unavailable => existing V1 core remains; runtime unavailable => typed error and no hidden fallback; expired schema => rediscovery and reapprove if changed; installation rollback atomic alias switch after smoke; failed update retains previous verified revision; restart reconciliation only managed recorded children with identity verification, no kill by name. No automatic paid calls.
