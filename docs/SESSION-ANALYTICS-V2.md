# Session analytics and token forecasting — V2 mandatory extension
Status: specified, not implemented. This document extends ORCHESTRATOR-V2.md; V1 gates still apply.
## Durable session ledger
Bridge sole SQLite writer. Add sessions (UUID, project/worktree/task/plan revision/attempt, provider, exact model, CLI version, reasoning effort, auth mode, pseudonymous account bucket, upstream session ID if available, start/end/status, parent/checkpoint session, git HEAD, dirty state), task_features (type, estimated complexity rubric, file count/size, language, expected edits/tests/tools, context pack size, dependency count, uncertainty), session_outcomes (acceptance, tests, duration, retries, review/rework, actual changed files), forecast_snapshots and forecast_actuals. Distinguish planned features available before execution from actual features; never train with leaked future outcomes. Include manual CLI sessions when telemetry and consent allow; mark unlinked sessions and incomplete coverage. One task can span sessions/attempts; include failures, retries, planner and reviewer costs; dedupe cumulative counters using documented provider semantics, sequence/checkpoint and source event IDs; never sum repeated cumulative snapshots. Missing counters null not zero; record measured vs estimated vs unavailable, source, time, unit and model/pricing version. No double counting cached input/reasoning subsets. Reconcile partial/cancelled sessions and restart. Store locally with persistent volumes, backup/restore and migrations.
## Privacy and retention
Default metadata + bounded redacted handoff only. Optional transcript archive explicitly enabled per project; local-only, separate protected storage, configurable retention/delete/export, redact credentials/PII, no raw reasoning or unauthorized provider export. Never read private CLI files unless supported/authorized; do not store credentials or prompts in Git. Default detailed metadata retention 180 days, configurable; retain anonymized aggregate statistics only with consent. Deletion applies to derived samples and forecasts as appropriate; rebuild aggregates; document backups and deletion limitations. Project isolation default; opt-in cross-project aggregate learning without source text or identities.
## Complexity and classification
Use preflight deterministic features: type (architecture, debugging, implementation, UI, tests, review, docs, routine), language, relevant files, expected change scope, dependencies, uncertainty, tests, context pack estimate. Complexity rubric XS/S/M/L/XL defined by expected scope, uncertainty and validation effort, not token count alone. User can override before approval; preserve rubric version. Estimate context pack with model-specific supported tokenizer if available; otherwise label approximation. Never equate prompt size with total billed input over multi-turn session.
## Forecast engine
Deterministic local statistics, no paid LLM. Cohort exact model/effort/auth mode/task class/complexity/project where sufficient; time-decay and model-version separation. Include successful and unsuccessful attempts, forecast total cost-to-acceptance incl retries/handoff/planning/review. Use empirical median and upper quantile (P50/P90) separately for input/output/cache and total from joint samples; do not sum independent quantiles and call it a calibrated plan P90. Initial configurable thresholds: >=20 comparable complete observations for cohort quantiles, >=50 for high confidence only if backtest calibration adequate; 5–19 low-confidence pooled estimate, <5 cold-start heuristic range or unknown. Hierarchical fallback to explicitly permitted broader cohort, shrinkage and provenance; no invented observations. Return sample counts, date window, matching criteria, model/effort, forecast version, confidence, assumptions, missing coverage. Estimate plan totals by summing expected values and using joint/resampled task distributions for ranges with stated correlation assumption; account for concurrency, retries, shared planning cost and fallback without double count. Report lower/upper ranges for each task and plan, not false precision. Monitor rolling holdout MAE/WAPE and empirical P90 coverage; avoid percentage errors at zero; detect drift, recalibrate after new outcomes/model updates, label uncalibrated. No automatic dispatch based solely on weak forecasts; require explicit budget/approval when material uncertainty.
## Quota and cost forecast
Separate task token budget (forecast tokens / user-set task budget), context peak (predicted peak live context / verified context limit, not cumulative input), API spend (applicable versioned input/output/cache pricing and account budget remaining), provider rate/request windows and subscription quota. Only compute subscription percentage when documented usage unit and denominator/reset window exist and forecast maps to same unit via supported telemetry or calibrated empirical model with clear uncertainty. Never divide tokens by context window to infer subscription usage; never infer provider quota from local token count. Account-scoped quota deltas may include concurrent/external activity; isolate attribution or label confounded/unavailable. Forecast rate limit pressure over time, not total task tokens divided by TPM. If denominator unavailable show 'Không có dữ liệu'; optionally show historical comparable tasks and observed quota-exhaustion risk without fake percentages. Display incremental percentage points of total limit and percent of remaining allowance distinctly, reset/window and data freshness; don't combine separate providers/windows. Reserve approved internal budget atomically for parallel tasks; release unused amounts, stop/checkpoint at policy limit; actual usage may lag and hard provider caps only where supported. Reapproval for material forecast increase or model/scope change unless explicitly covered by auto policy.
